# P05 Public Catalog Interface Contract

This is the Phase 1 design for the changed browser/server interface. Implementation must define these as browser-safe strict Zod schemas and inferred input/output types in `@fury/contracts`, reuse them in API DTOs, parse actual responses at web boundaries, and update `apps/api/src/infrastructure/openapi/openapi.ts`. Existing `GET /api/v1/content/works`, `/{workSlug}`, `/{workSlug}/chapters`, and `/{workSlug}/chapters/{chapterNumber}` retain their current wire shape.

## Authority and common HTTP rules

All P05 API paths below are under `/api/v1`. They are anonymous `GET` reads: visitor, authenticated active/verified user, ADMIN, any later moderator role, and crawler receive the same public projection. Do not run authentication or CSRF middleware on them; do not forward browser cookies or bearer tokens from the public JSON adapter. Passive same-origin image requests may carry ambient cookies, which the image route must ignore. Existing ADMIN content writes remain authenticated, active/verified, role-checked and CSRF-protected. The global request ID, logging, helmet, CORS, JSON and API rate-limit middleware remain in current order before the content router. There is no P05 owner write or moderation authority.

JSON success uses the existing envelope `{success:true,statusCode:200,message,data,paginationMeta?,requestId,timestamp,path}`; `data` is the strict endpoint shape below. For catalog works and categories lists, the existing response helper supplies top-level `paginationMeta` equal to `data.pagination`; it is absent for home, detail and sitemap. JSON failures use `{success:false,statusCode,code,message,errors?,requestId,timestamp,path}`. Allowed common failures are `400 VALIDATION_ERROR` with `{field,message}` entries for parsed schema failures, `400 BAD_REQUEST` without a fabricated field path for malformed URL encoding, `429 RATE_LIMIT_EXCEEDED`, `500 INTERNAL_SERVER_ERROR`, and `503 SERVICE_UNAVAILABLE`. Detail and image routes additionally use `404 NOT_FOUND` for unknown/nonpublic work; unknown P05 route paths also use safe `404 NOT_FOUND` without echoing the raw path. Binary image success is the only response outside the JSON success envelope. No public error includes a Prisma/provider message, storage path, private existence hint, token or secret. Malformed and unknown P05 path failures use a non-sensitive envelope path; public catalog request logs retain request ID and safe route identity but not search terms or raw malformed/unknown URL values. Existing and new public content JSON/image responses have `Cache-Control: no-store` on success and failure, including a limiter `429` before the content router; intermediaries must honor it.

Query and params are strict: unknown keys, repeated scalar keys, unsupported enum values, unsafe control characters and overlong values yield `400 VALIDATION_ERROR` at their parsed path (`query.q`, `query.sort`, `query.category`, `query.page`, `params.workSlug`, etc.). Malformed raw percent encoding in a path or query yields `400 BAD_REQUEST` without a fabricated field path or raw URL disclosure. `q` is trimmed/NFC, at most 100 characters; an empty normalized query is omitted. `page` is a decimal integer from 1 through 1000, a technical query bound rather than a catalog-size claim. `workSlug` uses the existing normalized lowercase 1–120 character content slug; case/whitespace normalization follows that contract. Optional query fields are omitted in canonical URLs, not sent as empty strings or `null`. The web URL model drops malformed or unsupported selections and replaces the URL with its normalized state; direct API calls still receive validation errors. A syntactically valid disabled/unknown category slug remains selected in the URL and returns a 200 filtered-empty result without a category-existence signal.

## Shared public projections

| Shape               | Fields and constraints                                                                                                                                                                                                                                                                                                                                         |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CatalogCategory`   | `slug` (public canonical category slug), `displayName` (1–100 Unicode characters). No admin enablement/version/count field.                                                                                                                                                                                                                                    |
| `CatalogWork`       | `slug`, `title` (1–200), `alternativeTitle: string\|null`, `type` (the existing six work types), `storyStatus` (the existing four statuses), `publishedAt` ISO timestamp, `categories: CatalogCategory[]` in enabled saved order, `coverPath` (safe root-relative work-scoped API path). No media asset ID, raw storage URL, rating/open count or admin state. |
| `CatalogWorkDetail` | `CatalogWork` plus `synopsis` (20–5000), `author` (1–150), `artist: string\|null`, `tags: string[]` in saved order (at most 20), `backgroundPath: string\|null`. Background is nullable; cover is required for eligible work. Omitted editorial values are not invented.                                                                                       |
| `CatalogChapter`    | `number` (positive integer), `title` (1–200), `contentType` (`illustrated` or `text`), `publishedAt` ISO timestamp. It is a summary only: no body, page IDs/paths or read/open action.                                                                                                                                                                         |
| `Pagination`        | Existing `{page,limit,total,totalPages,hasNextPage,hasPreviousPage}` contract. An out-of-range page preserves requested `page`, yields `items:[]`, `hasNextPage:false`, and a UI return-to-first-page action. `total=0` means the eligible filtered set is truly empty.                                                                                        |

`null` means an optional saved value or no eligible first/latest chapter; empty arrays mean a completed read found no items. Loading, error and unknown are transport/UI states, never represented as successful empty arrays. Safe `coverPath` and `backgroundPath` are generated from public work slug and route, never from a media asset identifier. The web composes them with the configured externally reachable API origin for image/OG use; paths must not permit off-site redirects. Failed or corrupt cover bytes while the saved asset remains `AVAILABLE` produce an image `503 MEDIA_UNAVAILABLE` and leave the work eligible. Only a committed asset-status transition to `UNAVAILABLE` removes it from subsequent public reads; verified restoration can make a later read eligible again.

Fixed home bounds are five featured works, twelve category shortcuts, twelve latest releases, and at most three suggestion categories with six works each. These are bounded presentation selections, not business KPIs. Suggestion tabs select the first three enabled categories in saved display order that each contain at least one eligible work. Within a tab, works are distinct and ordered by newest publication then unique work ID; a work associated with several selected categories may appear in each corresponding tab. Empty enabled categories remain directory choices but do not consume suggestion tabs. If a section has no eligible items, return `[]`; the UI hides or explains it truthfully. No fixed category-label fixture is a fallback.

## Selection, ordering and visibility

- The API applies shared public work readiness first: published work with required editorial fields, at least one enabled category and an active AVAILABLE ADMIN cover reference. Chapter summaries require the existing P04 published/readiness rule beneath an eligible work. A valid public cover URL is re-authorized at each byte request. Existing ADMIN management refuses disabling a published work's last enabled category; a permitted disable removes that category from public choices while the work remains eligible through another. The public read still fails closed for legacy or operationally inconsistent records with no enabled category.
- `/content/catalog/works` uses Unicode-normalized, case-insensitive substring search of title and available alternative title; category directory search applies the same comparison to display name. `view=stories` is enforced on the server, restricting to `novel` and `text-story`; a `type` outside those two with that view is a `400 VALIDATION_ERROR` at `query.type`. Filters intersect, and total is computed before pagination. No hidden-work count is returned.
- `newest` orders work `publishedAt` descending then unique work ID; `chapter-latest` uses latest eligible chapter publication time descending, with chapter-less works last, then unique work ID; title orders use a deterministic database collation plus unique work ID. A work appears once even if it has several matching categories or chapters. Equal keys produce stable traversal when the dataset is unchanged.
- Enabled categories order by saved `displayPosition`, then unique ID. Hero orders by published featured order, then unique ID. Latest releases order eligible chapter `publishedAt` descending, then unique chapter ID. Similar results share at least one enabled category, exclude the current work, deduplicate, then order newest/unique ID. First/latest mean the lowest/highest eligible chapter number under that work and derive from the full set, not just the initial page.
- `sitemap-works` assembles all currently eligible canonical slugs in one repeatable-read transaction using bounded keyset batches and exposes no IDs/cursors. The dynamic sitemap deduplicates the returned slugs and includes no chapter/protected URLs. A transition committed during the transaction may appear on the next fresh request, not partway through this response. No cached snapshot is treated as current. The complete response size follows the eligible catalog; monitor it and plan sitemap sharding if representative volume warrants it.
- All composite JSON reads make their eligibility, items and totals in one repeatable-read snapshot. Concurrent ADMIN transitions commit through existing P03/P04 authority; in-flight reads may finish under their earlier snapshot, while a subsequent authoritative read sees the new state. No P05 read writes a publication, chapter open, rating, bookmark, comment or progress event.

## Page URL and SEO interface

Owned public paths are `/`, `/discover`, `/stories`, `/categories`, and `/story/{slug}`. `/discover` and `/stories` expose normalized `q/category/type/status/sort/page` in shareable URLs; `/categories` exposes `q/page`. Search/filter changes reset page one. Query variants receive `robots.index=false, follow=true` and canonical `/discover`, `/stories` or `/categories`; the unfiltered base route is indexable. Work detail has one canonical `/story/{slug}` with Arabic-first title/description and Open Graph title/description/public cover. Hidden work gets the same not-found response as an unknown slug with no private metadata. The dynamic sitemap includes `/`, `/discover`, `/stories`, `/categories` and each currently eligible `/story/{slug}` once. Robots excludes account, admin and reader paths. Absolute canonical/sitemap/OG URLs use validated owner-configured site origin, never request `Host`. Community destination is separately validated HTTPS config and absent when unset.

## Compatibility and verification

The new routes share the existing content policy, envelope, stable error codes and API rate limiter. The four older public metadata routes are unchanged so independently deployed strict consumers do not reject added fields. Deploy API before web; a web client must runtime-parse each new endpoint. Contract and OpenAPI tests assert methods, schemas, optional `paginationMeta`, field paths and status codes. Supertest checks anonymous/signed-in parity, parsed validation versus malformed URL encoding, 404 hidden/unknown equality, public image integrity/failure, existing/new public `no-store` including pre-router `429`, and preservation of private `/media` access. Request-logger and HTTP tests assert sentinel search, malformed URL and unknown P05 path values are absent from emitted logs and safe errors. Real PostgreSQL tests assert filtering, ordering, totals, permitted category disable and last-category refusal, transitions, duplicate-free pages, and unchanged persisted publication/business-event counts after duplicate/retry GETs. Crawler/real-browser checks assert URL refresh and fresh SEO after unpublish.
