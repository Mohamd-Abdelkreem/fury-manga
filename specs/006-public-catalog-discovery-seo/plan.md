## End-to-End Architecture and Ownership

1. Initial route render and `generateMetadata` call the server-only public adapter, which sends credential-free, `no-store` GETs to the same Express public routes as the browser. They parse the shared envelope and output schema; 404 maps to Next `notFound`, while transport/5xx maps to unavailable with retry. Catalog search parameters are normalized before the request and reflected in the URL.
2. For client filter, pagination and retry actions: route/component → `public-catalog` hook → feature API adapter → central `apiClient` in explicit public mode → global Express request ID/log/helmet/CORS/body middleware and API rate limiter → content route validation → thin public controller → public content service → feature query and mapper → Prisma → PostgreSQL. Public GETs do not run authentication or CSRF middleware; ADMIN content commands retain auth + ADMIN + CSRF and existing response behavior.
3. The service owns shared publication/readiness decisions, composite read transaction and selection limits. `content.queries.ts` owns database predicates and ordered selections; `content.mapper.ts` emits only public DTO fields and work-scoped image paths. Controllers do not query or map database records. `router.ts` supplies database/media dependencies. No browser import of API/database code; no Prisma record crosses the wire.
4. Search, category, type, story status and sort are applied by the API before total and page selection. `/stories` uses the same catalog query with a server-enforced `stories` view and only `novel`/`text-story`; the web does not filter an all-type page after pagination. Public category links use category slug, and status/type values come from shared enums.
5. Detail reads include the public work projection, first page of eligible chapter summaries, first/latest eligible chapter from the full set, and bounded similar works in one repeatable-read snapshot. Further chapter pages use the existing public chapter-summary route. A 404 from a later chapter request revokes the detail view for that work until a new authoritative successful detail read.

## Contracts and HTTP Behavior

[contracts/public-catalog.md](contracts/public-catalog.md) is the interface design and authority matrix. Add `GET /content/catalog/home`, `/content/catalog/categories`, `/content/catalog/works`, `/content/catalog/works/{workSlug}`, and `/content/catalog/sitemap-works`; add `GET /content/works/{workSlug}/cover` and `/background`. The four existing public work/chapter endpoints retain their paths and wire outputs. All paths are below `/api/v1`; GETs have no body and use the existing success/error envelope except successful binary image bytes.

The shared Zod contract supplies strict params/query/output and separate input/output types because normalization/defaults transform inputs. Catalog URL/UI defaults are `view=all`, empty optional filters, `sort=newest`, `page=1` (maximum 1000), fixed `limit=12`; no public `limit` override. `q` is trimmed/NFC and bounded to 100 characters; slug/status/type/sort are allowlisted; repeated or unknown keys and unsafe control characters are invalid. Parsed schema failures return `400 VALIDATION_ERROR` with field paths. Malformed percent-encoding that prevents reliable parsing returns the existing safe `400 BAD_REQUEST` without an invented field path; the existing error boundary handles failures before route validation, and a bounded raw-URL check covers query encoding. Public catalog request logs retain request ID, method and safe route identity without `q` or raw malformed URL values; the safe error envelope uses a non-sensitive path for malformed path decoding. Web URLs remove malformed or unsupported selections, but retain a syntactically valid unknown/disabled category slug so its API result remains filtered-empty instead of silently broadening results. Out-of-range pages return a 200 empty page with requested page in pagination metadata and a visible route back to page one. Equal sort values use immutable unique work ID as tie-breaker. The contract specifies omission/null behavior for optional details and image availability.

The browser adapter runtime-parses shared responses and classifies only safe known codes. The established success envelope has optional top-level `paginationMeta`: it is present and agrees with `data.pagination` for catalog/category lists, and absent for home, detail, and sitemap responses without top-level pagination. OpenAPI must agree with runtime method/path/query/security/status/envelope. New P05 routes avoid breaking old strict parsers; when deployed independently, API support lands before the web consumer, and old routes remain available. No endpoint accepts a mutation, CSRF token, actor or private media ID.

No raw asset ID, body, publication event ID or admin version in public DTO.

Home hero: eligible `featuredHome` works by `featuredOrder`, then unique ID; latest releases: eligible published chapters by `publishedAt` descending, chapter ID, tied to eligible parent works; suggestions: the first three enabled categories in saved `displayPosition`/ID order that each have eligible works, up to six distinct works per tab by newest `publishedAt`/ID, with a work permitted in each category to which it belongs; categories: enabled `displayPosition`, category ID. Similar works: shared enabled category, exclude current slug, unique work ID, stable newest order. Catalog newest: work `publishedAt` descending/ID; chapter-latest: maximum eligible chapter publication time descending, works without eligible chapters last, then work ID; title orders use deterministic database collation plus work ID. Search title and alternative title only; no rating/open-derived sorting. Bounded first-page and subsequent page queries compute total on the full eligible filtered set. Sitemap slug export uses bounded keyset batches by immutable work ID inside one repeatable-read transaction, returning one complete visibility snapshot; Next deduplicates the resulting canonical slugs. The complete response size follows the eligible catalog and must be monitored for a later sharding need. Representative `EXPLAIN` evidence is required before any optional forward index migration.

Publication/category/media changes remain P03/P04/P02 transactions and history. P05 never deletes or backfills records. P03 refuses a category disable that would leave a published work with no enabled category; successful disablement removes the category from options while a work retains eligibility through another. The P05 read policy also fails closed for legacy or operationally inconsistent records with no enabled category. A failed byte read does not itself change saved asset state; a committed `UNAVAILABLE` state does change eligibility. A new read after a committed change re-evaluates eligibility; in-flight responses may reflect their transaction snapshot but are not used to override a newer denial. Failed schema/index experiments roll back by reverting application usage or a new forward correction; no applied migration is edited.

## Frontend and SEO Behavior

- Public React Query keys contain only normalized `view/q/category/type/status/sort/page` or public slug/section; no token or actor-specific data. Initial server DTOs seed only their matching public query key, with React Query owning subsequent browser freshness and no parallel local catalog copy. Each request uses an abort signal. On URL change, show loading/previous-result context without presenting an old work/page as current; reject late completion by key. A newer work 404 evicts stale detail/related/image assumptions and remains authoritative until a later matching work success. A newer chapter 404 invalidates cached chapter references and chapter-derived detail, then refreshes the parent work; it does not by itself hide that work. Background refresh may keep visibly stale context, never a withdrawn work after denial. No form draft or mutation conflict is introduced.
- Search/filter changes reset page one and retain compatible selections; page links preserve normalized query. A syntactically valid unknown or disabled category slug stays selected and yields an authoritative filtered-empty result; it must never be dropped to broaden results. Categories directory name search is URL-backed and paginated; enabled-only result. Catalog-empty, filtered-empty and out-of-range states are distinct. Slow, 429, 500/503 and network failures have Arabic status/retry copy; retry is pending until response succeeds. Home sections without authoritative items disappear or show intentional empty content. No synthetic trend, rating, comments, member counts or live read button. First/latest chapter numbers remain informational until P07 can serve them.
- Reuse approved dark Arabic RTL design, cards, layout, navbar and responsive grids. Render original titles safely in their own direction; semantic headings/landmarks, names, keyboard filter/carousel/pagination operation, visible focus, live status/error announcements, adequate target size/contrast and reduced-motion behavior are implementation acceptance. Manual browser checks cover narrow and wide viewport, keyboard, mixed Arabic/Latin title, retry focus and browser back/forward.
- `generateMetadata` reads the same live public detail as the page; eligible work gets Arabic-first title/description, canonical slug, Open Graph title/description and accessible public cover. Hidden/unknown work calls not-found with no private metadata. Home, unfiltered discovery/stories and categories are indexable and canonical. Every query variant remains shareable but gets `noindex,follow` and an unfiltered catalog canonical. `robots.ts` excludes account/admin/reader paths; `sitemap.ts` is dynamic and includes only root public routes plus eligible canonical work slugs once, never chapter URLs. Request-time/no-store reads avoid stale Next static output after publication transitions. Validate production HTML for social crawlers and test against any CDN caching at release.
