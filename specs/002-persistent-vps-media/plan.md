**Phase boundary**: This is design only. No application code, migrations, deployment, or parent-record editing is authorized by this plan. The separate tasks phase has since produced `tasks.md`.

## Summary

Build a private, validated six-class media pipeline on the existing Express/PostgreSQL stack with bytes on a persistent VPS directory. Upload attempts are retryable without duplicate accepted assets; media identities are immutable; Work/ChapterPage reference operations prove replacement/removal safety without implementing P03/P04 parent editors. The existing Arabic RTL previews gain truthful upload state. Avatar candidates are owned privately; editorial/gift assets are ADMIN-managed. No unbound asset becomes public. Technical decisions and evidence are in [research.md](research.md); model and exact HTTP surface are in [data-model.md](data-model.md) and [contracts/media-http.md](contracts/media-http.md).

## End-to-end Architecture and Ownership

The upload path is affected client control → media React Query command hook (in-flight guard, progress and attempt state) → media feature API (FormData/shared schema, safe error) → central `apiClient` (current bearer/refresh and CSRF) → Express `/api/v1/media` route (auth, CSRF, scoped rate, bounded multipart parser) → thin controller → media service (class/owner/invariant and attempt state) → feature queries and explicit mapper → Prisma/PostgreSQL plus injected filesystem/image adapter. Metadata/list/reference reads follow the same path without multipart. Binary read uses the same authenticated transport but returns validated bytes, not JSON; the feature hook keeps an ephemeral blob preview outside Query cache. `apps/api/src/router.ts` constructs the service/adapter and mounts routes. No Express/Prisma provider crosses into `@fury/contracts` or the browser. No raw database object becomes a DTO. Apply B01–B08/B12–B16/B27–B29/B31/B34/B36/B38/B40–B49 and F01–F08/F20/F21/F24–F31 as relevant.

Service-owned operations: reserve/resolve an upload attempt; validate and publish bytes; list/lookup/deliver with class/owner checks; bind/replace/retire references; refuse or complete physical removal; reconcile interrupted states. Query helpers own deliberate selects, live-reference predicates and bounded pagination; mappers allowlist outputs. The storage adapter owns path containment, secure staging, rename/unlink/read, hash verification and decoder isolation. Controllers select status/envelope and await services; no transaction, file I/O, or role decision belongs in a React component or controller. The page layout remains composition/presentation only. A media reference service is feature-local because file lifecycle needs the same lock/access policy; no speculative generic asset registry.

## HTTP, Authority and Threat Boundaries

[media-http.md](contracts/media-http.md) is the method/path/schema/status authority matrix. `@fury/contracts` owns strict input/output schemas and wire enums, with `z.input` for caller values and parsed `z.output` for service inputs. Multipart parser results are validated against shared class/header/form schemas; bytes undergo separate streaming/decode validation. The existing JSON envelope, `AppError`, `validationMiddleware`, field-path convention and OpenAPI builder remain. Additive routes do not alter P01 content or account DTOs. Every client-facing JSON response is runtime parsed at the feature API boundary; binary headers/type are checked before preview. The OpenAPI change must describe multipart, binary and auth/CSRF truth, not claim a JSON file body. Newly deployed browser code must be paired with the additive API; old clients remain compatible.

| Actor/boundary                            | Allowed P02 outcome                                                                                                                                     |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Public visitor                            | No unbound P02 asset metadata or bytes. Missing bearer is 401 on media routes. Future public visibility belongs to later publication/binding phases.    |
| Active, verified USER                     | Upload/list/read/remove only own avatar candidates; no editorial/gift asset authority or cross-user avatar lookup.                                      |
| Active, verified ADMIN                    | Manage five admin classes and P02 Work/ChapterPage references; may manage own avatar as an owner, but ADMIN role alone grants no other user's avatar.   |
| Pending-verification or suspended account | Existing auth middleware rejects every media route before record/file lookup; no mutation.                                                              |
| Moderator or unsupported role             | No privileged media role is implemented; server denies admin-class commands.                                                                            |
| System operator/recovery process          | Filesystem/database backup and reconcile under restricted operational credentials; no browser impersonation, public URL, or alternate media auth token. |

Unsafe bearer-session commands retain the current double-submit cookie/header CSRF check. Static auth and CSRF run before body parse; class-specific role/ownership checks run as soon as bounded class/target identity is parsed and are repeated in the service. Existing global rate limiting remains; a media-specific bounded upload limiter runs before byte processing, with process-local limits documented rather than asserted to cover a multi-instance VPS. Do not accept owner ID, file path, redirect URL, storage key, or class from query/body where the contract excludes it. Return 404 for an inaccessible protected asset, attempt, or reference and 403 for known command/scope role denial without private lookup. The upload attempt key is scoped to the authenticated actor; the same UUID used by another actor starts an independent attempt and reveals nothing about the first. Direct bytes and metadata use the same policy. Protected responses use no-store, safe MIME/disposition/nosniff, no public optimizer/CDN cache, and no embedded original metadata.

Threat/failure review: extension/MIME/content deception and decompression bombs → finite stream/decode limits and full decode; executable/polyglot/metadata abuse → strict allowed formats and clean re-encode; traversal/symlink/root swap → server key only, canonical root containment and no-follow file operations; cross-owner guessing → service check and nondisclosing 404; CSRF/abuse → existing middleware plus upload bound; lost response/duplicate → actor-scoped attempt; stale write/removal race → lock/CAS/partial unique; disk full/crash → pending/removing recovery without false success; corrupt/missing file → unavailable response and redacted reconciliation record. Test sentinel paths, tokens, private IDs and exception text absent from envelopes/logs/QueryCache. A request ID and safe code are enough for user support; never log raw multipart bodies or file bytes.

## Data, Transactions and Recovery

[data-model.md](data-model.md) defines `MediaAsset`, `UploadAttempt`, `MediaReference`, and immutable `MediaReferenceEvent`, including nullability, FKs, constraints, indexes, transitions and retention. Existing rows are not backfilled with invented media. The migration is additive and forward-only; update schema inventory tests and test fresh, populated and repeated migration deploys. P01 public projections remain media-free. Reference target checks use real P01 Work/ChapterPage FKs; future gift/profile links require their owner phases.

For an upload, uniqueness on actor/attempt key and one accepted asset per attempt prevents duplicate accepted work without exposing another actor's key. Reserve the attempt and pending asset together, stage/canonicalize/flush, record the canonical hash, then rename before DB `AVAILABLE`; pending and orphan files are never served. If acknowledgement is lost, the actor queries the same attempt key. A bounded reconciliation run accepts only provably complete validated final bytes and committed identity; otherwise it settles the attempt as `REJECTED` with safe `UPLOAD_INCOMPLETE`, retires its reserved asset, and requires a new key for another upload. For bind/replace/retire/removal, lock asset rows in deterministic order, check the target and live uses, use expected version/current ID, then commit the reference transition and its immutable event. Partial unique indexes enforce one active target use; FKs prevent dangling targets/assets. A referenced asset removal is `409 MEDIA_IN_USE` with no queued unlink. New binds cannot race with `REMOVING`; repeated exact commands give stable results; stale commands return conflict and preserve the prior active bytes. These invariants require real PostgreSQL competing-request tests, not application prechecks. Filesystem work is outside long transactions and its partial failures remain recoverable states. Reconcile only bounded records/keys with a manifest and no blanket deletion. Binary GET reports missing/corrupt bytes safely; only the controlled reconciliation operation changes persisted availability.

Release order: confirm P00/P01 gates and P02 reviewer disposition → take a database/media backup of any existing environment → apply new migration → create/verify private persistent root and environment configuration → deploy API → deploy web controls → exercise upload, denial, restart and restore on staging → review P02 gate. Fail startup for an unsafe initial media root; if storage becomes unavailable later, existing `/health/ready` returns its established `503` degraded **success** envelope with `database: "ok"` when the database itself is healthy, while `/health/live` retains liveness semantics. The current OpenAPI entry incorrectly labels that existing 503 as an error envelope for database failure; correct it to describe the actual degraded success envelope and both database/storage causes. Do not add an unreviewed field to the health DTO or silently fall back to release-local storage. An old API can run against additive tables during rollback; retain DB rows/files and use the prior binary while correcting the new release. Reconcile pending/removing and verify hashes before reenabling media; never use migration down/reset or delete assets as a rollout shortcut. The runbook must prove a clean restore including at least one live reference. Production root permissions, backups, proxy/cache headers and deployment topology remain unverified until environment-specific exercise.

## Frontend Behavior and Visual Preservation

Keep `AdminWorkMediaFields`, illustrated page reorder/preview, `AvatarPicker`, gift preview/dialog, Arabic labels and RTL layout. Replace sample-image actions and object-URL-only avatar completion with actual media selection/upload/progress/attempt lookup. Do not change `AdminDataProvider` work/chapter/gift record truth in P02. A media asset can be uploaded and previewed without saying the parent Work, Chapter, grant, publication, or selected profile avatar was saved. A form-level local mock success must be visibly separate from asset success; P03/P04/P10 retire those parent actions later. Existing admin guard remains visual only; every request is checked on the server.

Media Query keys include actor/session scope, asset class/list filters/page, asset ID, attempt ID, and target kind/ID. On login/logout or account change, cancel in-flight reads, revoke blob URLs and remove prior scope's private cache; no global store. Upload success invalidates the matching list and populates only that asset; reference mutation invalidates its target and relevant asset/use data; removal invalidates the matching list/detail. Request cancellation and a per-control generation/attempt ID prevent an old upload/preview response from replacing a newer selection or another resource's view. The selected `File`, temporary preview URL, progress, dirty parent form fields, and abort controller stay transient. A cancelled browser request may have committed server-side, so keep the attempt ID and resolve it through the authoritative attempt GET before claiming failure or retrying. A reconciled `REJECTED` attempt shows safe `UPLOAD_INCOMPLETE` and offers a new upload with a new key; the old key cannot create media. Do not put raw file/blob, original private filename, bearer, Axios error, or response bytes in Query keys/meta/mutation variables/data/errors; adapt a safe error before cache storage. A 401/403/404 terminal denial closes only its resource scope and persists through stale cache/late completion until a newer matching authorized GET; a transient 503 preserves known detail visibly stale with retry, without enabling unsafe actions.

Affected controls distinguish first loading, empty and filtered-empty asset list, background refresh, local preview, upload transfer, server validation pending, accepted asset, rejected validation, unknown/lost outcome, retry, stale/conflict, referenced-removal refusal, access denied, and storage unavailable. Progress reaching 100% means bytes transferred, not accepted. Retry uses the same attempt if outcome is uncertain; a new user choice uses a new attempt. Preserve draft and illustrated order on upload failure and conflict. Explicit Arabic messages map stable safe codes; field errors target the file/class/attempt field. Focus moves to the new error or success status when needed without stealing focus on every progress tick. Buttons and handlers prevent duplicate keyboard/pointer submission; file input has a label and hint, status/error use live regions, previews have meaningful alt text, and state is not color-only. Validate 320px and larger RTL layouts, keyboard/Escape/focus restoration in existing dialogs, mixed-direction filename handling, contrast and reduced motion. Read installed Next.js 16 guidance in `apps/web/node_modules/next/dist/docs/01-app/01-getting-started/05-server-and-client-components.md`, `12-images.md`, and `03-api-reference/02-components/image.md`; client browser APIs remain below client boundaries and private blob previews use unoptimized images.
