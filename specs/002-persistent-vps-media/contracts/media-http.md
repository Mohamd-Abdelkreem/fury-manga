# P02 Media HTTP Contract

Base path is `/api/v1/media`. This is the proposed browser–Express interface for implementation and OpenAPI; it does not expose a public media URL. Shared browser-safe Zod schemas in `@fury/contracts` own every JSON body, params, query, output and error-code enum. Inferred `z.input` describes caller input; `z.output`/`z.infer` describes parsed output. API DTO modules alias those exports. Multipart bytes use a bounded parser plus the shared scalar/form/header schemas; no TypeScript type is treated as runtime file validation.

## Common wire rules

- UUIDs are canonical lower-case UUID strings. Path values reject separators, percent-encoded alternatives, dots, traversal, NUL and extra segments. All JSON input objects are strict; unknown fields and unsupported owner/role/status claims fail `400 VALIDATION_ERROR`. Omitted fields and `null` are distinct; no P02 write uses `null` as an implicit clear.
- Success JSON uses the existing `SuccessEnvelope<T>` with `success`, `statusCode`, `message`, `data`, optional `paginationMeta`, `requestId`, `timestamp`, `path`. Error JSON uses existing `ErrorEnvelope` and stable media codes. Field errors use `body.*`, `query.*`, `params.*`, or `headers.idempotency-key`; no raw parser exception appears. Output schemas are strict, parsed by the feature API at runtime, and mapper tests assert absent private fields.
- `MediaClass`: `work_cover`, `work_background`, `chapter_page`, `user_avatar`, `avatar_frame`, `comment_decoration`. `MediaAssetDto`: `{id, mediaClass, status, contentType, byteLength, width, height, contentPath, createdAt}` for available managed assets; `contentPath` is server-built `/api/v1/media/assets/{id}/content` and conveys no public authority. No owner ID, uploader ID, file key, absolute path, original name, hash, or storage diagnostic.
- `MediaAttemptDto`: `{id, mediaClass, state, assetId, safeFailureCode, createdAt, completedAt}`. The attempt ID is unique within its actor's scope. `assetId` is UUID only when accepted, otherwise null, even if an internal pending asset was reserved; `safeFailureCode` only when rejected, otherwise null; `completedAt` null while pending. The response cannot claim an asset available until the asset and bytes agree.
- `MediaReferenceDto`: `{id, targetKind, targetId, assetId, version, createdAt, updatedAt}` for an active reference. `targetKind`: `work_cover`, `work_background`, `chapter_page`. Retired records are not returned in target lookup; direct stale reference lookup returns 404 for a retired record unless the response is the actor's just-completed retire command.
- All JSON responses have `Cache-Control: no-store`. Binary success has `Content-Type` from validated stored bytes, exact `Content-Length`, `Content-Disposition: inline` with a server-generated safe filename, `X-Content-Type-Options: nosniff`, `Cache-Control: private, no-store`, and no source metadata. No ranges, public CDN, public cache, redirects, alternate upload format, or `HEAD` contract in P02.

## Authority and route matrix

Global order remains request ID → redacted request log → Helmet → CORS → cookie parser → compression → JSON/urlencoded parsers (multipart is handled only at its route) → API global rate limit. Media POST order is authentication (current active and verified account) → CSRF → upload-specific limiter → bounded multipart/form/header validation → class role check → thin controller → service/query/storage adapter. Non-multipart routes validate scope/IDs and check role before object lookup; object ownership and current availability are rechecked in the service close to data. Final not-found/error middleware remains global. The existing in-memory API rate limiter applies; document that the upload-specific limiter is process-local until production topology is verified.

There is no P02 public visitor endpoint. Missing and inaccessible protected asset/attempt/reference IDs all return the same outward `404 NOT_FOUND`; a wrong role on a declared class/scope command returns `403 FORBIDDEN` after valid authentication, without disclosing a private record. Pending-verification and suspended bearer sessions fail existing `401 UNAUTHORIZED`. ADMIN is the only implemented privileged role; no moderator privilege is inferred. ADMIN does not inherit another user's private avatar. Read requests do not take ambient cookies as an alternate authority and do not mutate business state.

### Upload

`POST /assets` requires `Content-Type: multipart/form-data`, one `mediaClass` UTF-8 field followed by one `file` part, and `Idempotency-Key: <UUID>`. The class field must precede the file so the actor-scoped attempt and class-specific limits can be reserved before streaming; missing, duplicate, or out-of-order fields fail `400 VALIDATION_ERROR` at `body.mediaClass`. No other parts/fields/headers that claim owner or path are accepted. Source filename is checked for a supported extension but never used as a path or returned. Stream limits are one file, one field, two parts, a small bounded field/header size, and a per-class byte limit including an overall request cap. Missing/empty/cancelled file input is `400 VALIDATION_ERROR` with `body.file`. Unsupported/mismatched type is `415 MEDIA_UNSUPPORTED_TYPE`; corrupt/non-decoding/animated/transparency/dimension violations are `400 MEDIA_INVALID_FILE` with `body.file`; excess bytes/pixels/resources are `413 MEDIA_LIMIT_EXCEEDED`. Key comparison is actor-scoped: two actors using the same UUID create independent attempts and cannot inspect each other's outcome. For the same actor, a key already pending yields `409 UPLOAD_IN_PROGRESS`; a key reused for another class, different source bytes, or any new upload after rejection yields `409 UPLOAD_ATTEMPT_CONFLICT`. An exact accepted replay returns the same asset identity with `200`. If transport acknowledgement is lost, `GET /uploads/:attemptId` reports the actor's authoritative pending/accepted/rejected outcome; a pending result is never shown as saved. After reconciliation, an incomplete or unprovable interrupted attempt is rejected with safe `UPLOAD_INCOMPLETE` and cannot be reused. Fully validated final bytes may be accepted under the original key only after the asset identity and bytes are verified and committed. An attempt absent because reservation never committed returns 404 to its actor; a new submission may use that key because no attempt exists. Safe rejected attempt details are allowlisted only.

All classes have a 24,000,000 decoded-pixel ceiling, one frame, and a bounded decoder resource budget. Cover/background/page/avatar support JPEG/PNG/WebP; frame/decoration support PNG/WebP only. Supported extension, declared MIME, detected decoder format, and canonical output must agree. The limits are P02 validation defaults requiring representative-artwork review at implementation kickoff, not performance or traffic promises. Browser hints mirror server values but cannot authorize upload.

### Lists and lookups

List query is strict. `scope` is required; `mediaClass` is optional only if consistent with scope. `page` defaults to 1, `limit` to 25, max 100, reusing the shared pagination schema; no `null`, empty, negative, fractional, unknown filter, or unbounded request. Filter and count run against the same authority scope and available assets. Sort `createdAt DESC, id DESC`; `paginationMeta` uses the existing total/totalPages/hasNextPage/hasPreviousPage shape. Page beyond the end returns an empty `items` array and truthful metadata; first-page empty is distinct from filtered empty in the UI. A direct lookup of a removed asset returns 404, while a known authorized unavailable asset or a missing/corrupt file returns `503 MEDIA_UNAVAILABLE` without file path or private diagnostics. A failed binary read records redacted operational evidence; only a controlled reconciliation operation changes persistent availability state. A removal still in `REMOVING` returns 503 on repeat, never false 200; the actor can retry after reconciliation.

### References

`POST /references` body is strict `{targetKind, targetId, assetId}`; target ID is an existing P01 Work or illustrated ChapterPage. `GET /references` requires exactly `targetKind,targetId` and returns null only for a valid authorized target with no active reference. Binding rejects class mismatch, unavailable assets, or an existing different active reference. `PUT /references/:referenceId` body is strict `{assetId, expectedAssetId, expectedVersion}` and changes only the active asset pointer after the new asset is available. `DELETE /references/:referenceId` body is strict `{expectedAssetId, expectedVersion}`; it retires only the matching active reference. A stale version/current identity yields `409 VERSION_CONFLICT`; a conflicting target/bind yields `409 MEDIA_TARGET_CONFLICT`. A newly referenced asset cannot be physically removed by a stale delete. No endpoint saves/publishes the parent Work/Chapter/Gift or selects an avatar for the profile.

## Stable media error codes and safety

Add a shared `mediaOperationErrorCodeSchema` extending existing common codes with `MEDIA_INVALID_FILE`, `MEDIA_UNSUPPORTED_TYPE`, `MEDIA_LIMIT_EXCEEDED`, `UPLOAD_IN_PROGRESS`, `UPLOAD_ATTEMPT_CONFLICT`, `UPLOAD_INCOMPLETE`, `MEDIA_IN_USE`, `MEDIA_TARGET_CONFLICT`, `VERSION_CONFLICT`, `MEDIA_UNAVAILABLE`. `UPLOAD_INCOMPLETE` is a safe terminal attempt reason, not a successful asset response. `MEDIA_IN_USE` is the required referenced-removal conflict and never queues deletion. Internal/IO/decode faults become safe `503 SERVICE_UNAVAILABLE` or `MEDIA_UNAVAILABLE` for an authorized known asset, with redacted request ID only. No original name, storage key/root, hash, another owner, raw exception, or request body appears in outputs/logs/cache. Multipart data and blob errors must be normalized to safe feature errors before React Query retains them.

## Compatibility and OpenAPI

All routes and schemas are additive to P01. Existing work/chapter/account/public response shapes and auth transport remain unchanged. Old clients ignore new media routes; new clients use them only when the server advertises/deploys the P02 boundary. Register every route in `apps/api/src/infrastructure/openapi/openapi.ts`, including multipart requestBody, UUID header, bearer/CSRF security, binary response, exact error statuses, and JSON envelopes. Schema/mapper, OpenAPI route, central adapter, real Express, and browser tests must agree. A P03/P04/P10 consumer will need a separately reviewed compatibility change before exposing media in parent DTOs.
