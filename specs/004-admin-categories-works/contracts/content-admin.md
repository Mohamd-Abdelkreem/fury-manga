# P03 Browser–Server and Public Metadata Contract

Base path: `/api/v1`. `@fury/contracts` owns the strict Zod body/query/params/output schemas and inferred `z.input` versus parsed `z.output` types; `apps/api/src/modules/content/dto/content.dto.ts` only aliases/re-exports. Every JSON success uses the existing `ResponseHelper` envelope `{success:true,statusCode,message,data,requestId,timestamp,path,paginationMeta?}`; every failure uses the current safe error envelope `{success:false,statusCode,code,message,errors?,requestId,timestamp,path}`. `errors[].field` starts with `body.`, `query.` or `params.` and includes array indices, for example `body.tags.2` and `body.categoryIds.1`. Frontend parses the full expected success envelope at runtime and maps stable codes/field paths to Arabic feedback; no raw Prisma, Axios error or backend prose is a UI protocol.

## Authority and middleware matrix

| Route family                                                                  | Actor and transport                                                                                     | Middleware order after global request ID/logging/helmet/CORS/cookies/body parser/API rate limit                                                                                                       |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /content/works`, `GET /content/works/{workSlug}`                         | Visitor or any account, credential-free public read; no cookie/bearer/CSRF required and no auth refresh | Strict query/params → public controller → published/eligible service/query/mapper. Public unknown/private/legacy-ineligible slug = indistinguishable 404.                                             |
| Every `/content/admin/categories*` and `/content/admin/works*` GET            | Active, verified ADMIN bearer; no per-resource owner/moderator role                                     | Live authentication → ADMIN authorization → strict query/params → controller → service. Missing/invalid/inactive/unverified 401; active non-admin 403; unknown identity 404 only after authorization. |
| Every `/content/admin/categories*` and `/content/admin/works*` POST/PATCH/PUT | Same ADMIN bearer plus existing CSRF cookie/header match                                                | Live authentication → ADMIN authorization → CSRF → strict body/query/params → controller → service. No GET side effect.                                                                               |
| P02 `/media/references*` and `/media/assets*` used by editor                  | Existing P02 authenticated authority/class policy and CSRF on unsafe operations                         | Keep P02 middleware/response protocol; new published-work eligibility guard is server-side and shares transaction with reference mutation.                                                            |

The existing global rate limiter remains; P03 creates no anonymous command endpoint. Per-process limiter scope must be described accurately in deployment docs. Caller-supplied role, owner, publication event/time, reference state, asset path or version result is unsupported input. All inputs are bounded and `.strict()`; params are UUIDs or normalized slug. No browser import of API/database implementation.

## Shared field schemas

| Input                              | Presence, normalization and bounds                                                                                                                                                                                                                                      | Output                                                                             |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `id` on create                     | Optional UUID supplied by P03 UI for ambiguous-result recovery; if absent, server generates as P01 did. Duplicate ID conflicts, never overwrites.                                                                                                                       | Stable UUID.                                                                       |
| `slug`                             | Required on create; existing lowercase ASCII-hyphen normalization, 1–120; immutable thereafter. Optional unchanged legacy slug on PATCH is accepted, changed slug conflicts.                                                                                            | Always stored normalized slug.                                                     |
| Category `displayName`             | Required on create, optional PATCH; NFC+trim, 1–100, no unsafe control.                                                                                                                                                                                                 | Nonblank text.                                                                     |
| Category `enabled`                 | Omitted create defaults true; optional boolean PATCH. Omitted PATCH means unchanged; no null.                                                                                                                                                                           | Boolean, including disabled associations.                                          |
| Category `displayPosition`         | Server assigned positive integer; move body has adjacent positive target and expected version. No arbitrary create/PATCH position.                                                                                                                                      | Positive global position.                                                          |
| Work `title`/`alternativeTitle`    | Title required create and bounded 1–200 NFC+trim; alternative optional create/PATCH, nullable clear on PATCH, nonblank ≤200 when present.                                                                                                                               | Title string, alternative string or null.                                          |
| Work `type`/`storyStatus`          | P01 six canonical types and four story statuses. Type required create/immutable; story status required create/optional PATCH. | `synopsis`/`author`/`artist`       | Optional draft create/PATCH; null clears; empty string is rejected (UI maps blank optional control to null). Synopsis 20–5000 when present; author/artist 1–150. Publish requires synopsis/author. No unsafe control.                                                   | Nullable strings; no invented empty copy.                                          |
| `categoryIds`                      | Optional create/PATCH, array ≤100 UUIDs, unique IDs; [] explicitly removes all, omitted PATCH leaves unchanged. Newly added category must be enabled; existing disabled association may remain/remove.                                                                  | Admin detail categories in global order; list counts/usage from live associations. |
| `tags`                             | Optional create/PATCH, array ≤20; each NFC+trim 1–40, no duplicate after normalization; [] clears; omitted PATCH leaves unchanged.                                                                                                                                      | Ordered normalized strings.                                                        |
| `coverAssetId`/`backgroundAssetId` | Optional UUID or null on create/PATCH; omitted PATCH retains, null removes (cover removal refused while published); candidate upload alone does nothing. Server checks P02 admin scope/class/AVAILABLE and current reference.                                           | Current private asset UUID or null; never raw relative storage key.                |
| `featuredHome`/`featuredOrder`     | Omitted create defaults false/null. Enabling requires positive integer order; disabling requires null order. PATCH supplies pair together when changing preference/order; omission preserves both. Draft/archive may keep preference; published active position unique. | Boolean and positive order or null.                                                |
| `expectedVersion`                  | Required nonnegative integer for PATCH, move, state change and category-set replacement; no null. Version advances for any real editorial/media/category mutation affecting the Work or Category.                                                                       | Current nonnegative version.                                                       |
| `targetState` on work create/PATCH | Optional `draft`/`published` on create (default draft); optional `published` on PATCH for atomic save-and-publish. Pure unpublish/archive/restore use existing publication PUT. Direct `archived→published` refused.                                                    | Current publication state and current time; history only in authorized owner.      |

`z.input` is used at web form/API call sites before transforms; parsed `z.output`/inferred DTO is used after validation. Unknown fields fail `400 VALIDATION_ERROR` and no state changes. Null does not mean omitted; [] means explicit clear for sets. P03 output DTOs stay strict and allowlisted. `adminCategorySchema` adds `enabled`, `displayPosition`, `worksCount`; `adminWorkListItemSchema` is a bounded summary (identity, title/alt, type/status, featured, chapter count, current cover ID, version/timestamps), while `adminWorkSchema` adds synopsis/author/artist, ordered tags/categories and current cover/background IDs. No fixture-only `views`, activity, local image URL or raw database record becomes a DTO. Public `publicWorkSchema` retains the existing P01 `id`, `title`, `slug`, `type`, `storyStatus`, `publishedAt`, and eligible `categories` projection; it adds no work media URL or editorial-only fields. Producer/consumer, OpenAPI, and compatibility tests must retain the public `id` field.

The category move response has a dedicated strict `categoryMoveDataSchema` containing the affected pair; it avoids returning an unbounded collection. A boundary command submits the current position and returns unchanged with `displacedCategory:null`; the UI disables its boundary control. For an exact no-op with stale `expectedVersion`, compare achieved target first, then return authoritative current state; otherwise stale conflicts. The same-state publication response retains P01 `transitioned:false` semantics. A draft can save with no cover/category; only publish is readiness-gated.

## Error, privacy and compatibility details

- Reuse existing `VALIDATION_ERROR` 400 with `errors` for malformed/unknown/bounded input; `UNAUTHORIZED` 401 and `FORBIDDEN` 403 precede resource lookup. Unknown category/work ID for ADMIN is `NOT_FOUND` 404. Public private and absent slugs both 404. Do not disclose whether an inaccessible media asset exists.
- Extend `contentErrorCodeSchema` with stable `CONTENT_NOT_READY`, `CONTENT_CATEGORY_IN_USE`, and `CONTENT_FEATURED_CONFLICT`; preserve existing `CONTENT_CONFLICT`, `CONTENT_IMMUTABLE`, `CONTENT_TRANSITION_CONFLICT`, `CONTENT_STALE_WRITE`. Add `CONTENT_NOT_READY` to `mediaOperationErrorCodeSchema` and its OpenAPI responses for the affected direct work-cover commands. A readiness 409 includes safe field paths (`body.synopsis`, `body.author`, `body.categoryIds`, `body.coverAssetId`) without raw internal detail. A stale 409 returns no success and requires refetch; direct P02 stale media retains its existing `VERSION_CONFLICT` where applicable. Unknown errors remain safe 500; real temporary unavailability is 503, never a fabricated 200.
- No automatic mutation retry. For uncertain create, GET submitted UUID and compare saved identity/state; if absent, deliberate same-ID retry. For uncertain edit/transition, GET current Work and event pointer; if result cannot be proven, display unknown outcome with manual refresh, not success. The browser preserves unsaved form input. Cache invalidation follows confirmed response only.
- `openapi.ts`, shared schema tests, mapper tests, Supertest and web adapter tests must agree on all methods/paths/statuses/security and exact envelope. Test outgoing auth/CSRF after central interceptors. Existing P01 minimal requests remain accepted; expanded strict output schemas require a coordinated API/contracts/web deployment for independently deployed clients. There is no evidence of a supported external management client; do not claim seamless compatibility without that coordination.
