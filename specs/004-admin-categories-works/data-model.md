# P03 Data Model and Migration Design

The existing P01/P02 models and forward migrations are authoritative. This document defines changes only; it does not edit applied SQL or generated Prisma output. Contract field bounds are in [contracts/content-admin.md](contracts/content-admin.md).

## Entities and relationships

`createdAt`/`updatedAt` use existing timestamptz precision; API emits ISO strings. Optional editorial fields use database NULL for absent/cleared, not empty strings; draft may omit synopsis/author/cover/categories. `alternativeTitle`/artist may be NULL. Tags/categories are replaceable sets in an editorial save. Disabled category, archived work, media references and publication history are retained; no P03 hard deletion or retention timer.

## State and invariant transitions

- Work: existing `draft → published`, `draft/published → archived`, `published → draft`, `archived → draft`; reject `archived → published`. Same target returns unchanged. `publishedAt`/current event pointer are non-null only for published and must reference that work's event (retain P01 constraints/triggers). A work can publish with zero chapters.
- Readiness at publish and on any intentional edit of a published work: nonblank title/slug/type/story status, synopsis length 20–5000, nonblank author, one enabled category and one active available work-cover asset. Background, alternative title, artist and tags optional. A direct category disable/assignment removal, administrative media retirement/removal, or metadata edit must not make a published work incomplete. At each service and final database guard, evaluate the post-write state. System reconciliation must still be able to mark missing or corrupt stored media `UNAVAILABLE`; this is an observed failure rather than an allowed editorial mutation. Public reads then exclude the affected work, and a later `AVAILABLE` restoration requires verified bytes and a fresh readiness check.
- Featured preference: enabled requires positive order; disabled has NULL order. Active published positions are unique. Archive/unpublish removes the work from active placement without clearing editorial preference. Restore returns draft, retaining preference; a later publish can conflict if position is occupied.
- Category order: positions form a gapless 1..N sequence after each successful create/move, ordered by `(displayPosition,id)`; boundary move and already-achieved target are no-ops. No hard-delete means no compaction from deletion. Create appends `N+1` and move swaps adjacent positions, both revisions advancing.
- Public eligibility: only currently published works with complete available cover/readiness are selected, and only enabled categories are projected. Private/draft/archive/legacy incomplete identities are indistinguishable from absent by public direct read (404). P03 does not serve public cover bytes.

## Constraints, indexes and query bounds

- Keep existing slug uniqueness/immutable triggers, `WorkCategory` PK/FKs, media active-slot unique indexes, publication pointer checks and history immutability. Add named CHECKs for positive category position, featured order/pair, normalized/bounded tags, nullable editorial bounds, and category version nonnegative. Add the published-readiness cross-row constraint/trigger only after legacy remediation. It must reject intentional invalidating writes without blocking the reconciler's verified `AVAILABLE` → `UNAVAILABLE` failure observation; prove both paths under direct SQL writes and concurrent transactions.
- Category order unique constraint must allow a transaction-local adjacent swap (deferrable); add `(enabled,displayPosition,id)` and search-supporting indexes only for actual predicates. Work list indexes support publication/type/story filters and updated/created order with ID tie-break; title/alternative-title search uses a bounded case-insensitive predicate with an index chosen after inspecting query plans, not an unbounded in-memory scan. Chapter count has existing work FK index. Partial unique active featured order and tag composite uniqueness enforce races.
- Existing `paginationQuerySchema` defaults page 1/limit 25 and caps limit 100; P03 list schemas cap page at 100,000 (matching the existing media-list ceiling), bound normalized search, and check offset arithmetic. Count and rows use the same filter in a consistent transaction snapshot. Work sort ties use ID; `chapters` descending treats true zero as zero. Category list includes exact distinct association count. No total from a different filter or fixture.

## Transactions, locks, conflicts and retry

| Command                                           | Transaction/invariant boundary                                                                                                                                                                                                                                                                                 | Conflict/retry outcome                                                                                                                                                                                                                               |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Category create                                   | Serializable read of current maximum, insert at N+1 with unique slug/ID/position                                                                                                                                                                                                                               | One concurrent winner; duplicate ID/slug/position loses with safe 409. If acknowledgement is unknown, client GETs its supplied UUID before intentional retry.                                                                                        |
| Category move                                     | Lock moved category and adjacent neighbor in deterministic ID order; check expected version/position, swap under deferrable uniqueness, increment both versions                                                                                                                                                | Already at target/boundary returns unchanged; stale/serialization loser 409; never silently overwrite newer order.                                                                                                                                   |
| Category disable/enable                           | Lock category and affected published work rows in consistent order, verify each published work retains enabled membership; change state/version                                                                                                                                                                | In-use unsafe disable 409 with safe actionable code; no association deletion. A simultaneous publish/assignment must serialize and recheck.                                                                                                          |
| Work create/update/combined publish               | Lock existing work (when editing), relevant category/asset/reference rows in stable order; verify version and immutable slug/type, new enabled associations, media class/status, tag/category/featured uniqueness; write all dependent rows, ready state and publication event in one serializable transaction | Duplicate slug/ID/featured/tag/category or stale version 409/validation; failed create leaves no Work; failed edit leaves previous confirmed Work/relations/events unchanged. No automatic retry of submitted editorial changes after serialization. |
| Pure publication PUT                              | Existing transition row lock/CAS, extended post-state readiness and featured check; event in same transaction                                                                                                                                                                                                  | Same target idempotent with `transitioned=false`; unready 409 `CONTENT_NOT_READY`, with disallowed/stale conflicts using their separately contracted 409 codes; exactly one event per real publish.                                                  |
| Direct P02 administrative reference/asset command | Reuse active-slot/CAS and reference event; acquire parent Work lock, advance its version on real work-reference change, and reject any resulting published-work readiness loss                                                                                                                                 | Wrong class/missing/private 404, stale/media-in-use/unsafe retire 409; no broken active reference. System reconciliation of missing bytes fails public reads closed and flags remediation.                                                           |

Serialization failures are mapped to a stable stale/conflict result, not silently retried against updated editorial state. This avoids lost edits. Database uniqueness is the final arbiter, even when friendly prechecks pass. A timed-out client refreshes authoritative state; cancellation of HTTP observation is not proof of rollback. Old media files are not physically removed while referenced; P02's reference-aware lifecycle/reconciliation remains authoritative. No new external side effect or outbox is needed for P03.

## Forward migration and existing data

1. **Additive migration A**: Add nullable work metadata, featured fields/default, WorkTag relation and safe indexes; add nullable category order, backfill deterministic row numbers in one controlled transaction, then enforce non-null/positive/unique and enabled default. Do not change immutable IDs/slugs/types or authentication tables. Existing works remain valid drafts or previously published records; no invented synopsis/author/media. Fresh schema and populated upgrade tests must inspect exact data preservation.
2. **Compatibility deployment**: Deploy server contract accepting old minimal P01 requests and P03 requests; old chapter operations remain. New publish/edit safeguards prevent new invalid published works. Public metadata fail-closes for incomplete legacy published rows pending repair. An operator-only inventory against the existing database identifies each affected identity and missing fields/asset state; no new endpoint is required. Keep connected web gated until API/migration compatible.
3. **Explicit remediation**: Administrator completes each existing published record or transitions it to draft with retained history. Check zero invalid published records and media reference consistency. Do not silently demote in migration. Apply forward migration B with validated cross-row readiness guard/trigger and final constraints; test repeated deploy and failure leaving prior schema/data intact. If repair cannot finish, P03 acceptance blocks; preserve existing data and documented limited public visibility, not false launch readiness.
4. **Recovery**: Backup/restore PostgreSQL plus P02 persistent media together before rollout; rehearse restore in isolated environment. Application rollback must remain compatible with additive fields; do not reverse/drop applied migration or reset production data. A failed strict migration is corrected with a new forward migration after data repair. Verify direct SQL/Prisma constraint names, concurrency winners/losers, rollback after injected mid-transaction failure, and stable public privacy in Testcontainers.
