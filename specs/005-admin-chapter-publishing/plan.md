**Checkout branch**: `004-admin-categories-works` (the Spec Kit pointer is `005-admin-chapter-publishing`; no branch was created) | **Date**: 2026-09-26 | **Spec**: [spec.md](spec.md)

**PLAN.md phase**: P04 — Persistent Chapter Authoring and Publishing | **Dependency state**: P01 content, P02 private media, P03 Work administration, and existing authentication have executable code; required P02/P03 exit-gate dispositions and P04 specification/reviewer acceptance are not recorded. ## Summary

Connect the three approved Arabic RTL admin Chapter routes to durable Chapter and private media state. Add title, direct version-1 structured-text editing, atomic illustrated page-set saves with retained media history, truthful preview and publication controls, searchable Work-scoped management, and a public _metadata-only_ projection that hides content when an associated image becomes unavailable. Keep the existing Express route family, shared Zod contracts, Prisma/PostgreSQL content domain, central Axios transport, React Query ownership, and P02 upload capability. Do not connect the fixture reader or build P05/P07/P09 features.

## Technical Context

**Language/version**: TypeScript 5.9.3, Node 24, strict ESM; pnpm 11.17.0/Turborepo.

**Primary dependencies**: Next.js 16.2.12/React 19.2.8, React Query 5.101.4, React Hook Form 7.84.0, Axios 1.19.0, Express 5.2.1, Zod 4.4.3, Prisma 7/PostgreSQL, P02 private media. No new dependency is justified.

**Storage**: PostgreSQL through `@fury/database`; approved private filesystem media and existing media metadata/reference/event tables.

**Testing**: Vitest 4, Supertest against real Express composition, PostgreSQL Testcontainers, Testing Library/jsdom; real browser and responsive/device evidence for interaction and focus.

**Target**: Existing Next.js web app and Express API. Existing App Router pages are thin server wrappers around client feature components. Installed Next 16 local docs for pages/layouts, client components, fetching and caching were checked; React Query owns this client-side admin server state.

**Performance goals**: No unsupported throughput/latency target. Keep list pages bounded to 100 and avoid loading 100 full documents; inspect query plans for the selected filters/order if needed.

**Constraints**: Preserve approved Arabic RTL visual design and stable auth; no public body/page media delivery; text ≤500 blocks/512 KiB, pages ≤500, number ≤2,147,483,647, title ≤200, pagination defaults 1/25 and max 100. Require atomic save, version conflict, safe public projection and retained history.

**Scale/scope**: Three admin Chapter routes, existing admin/public Chapter APIs, P02 Chapter-page association handoff, shared renderer for later P07 reuse. No invented traffic or business target.

### Ownership and dependency path

`page.tsx` supplies route params → Chapter client component and RHF/transient draft → feature `model` validates/shapes canonical command → React Query feature `hooks` own actor/Work/Chapter server state and mutation reconciliation → feature `api` runtime-parses shared envelopes using central `apiClient` → Express content/media routes with auth/role/CSRF/validation → thin controller → Chapter/publication/public services and feature-local queries/mappers → Prisma → PostgreSQL. Media upload uses existing P02 adapter; candidate transfer precedes Chapter transaction. No browser import of API/database or raw Prisma DTO.

The service owns eligibility/readiness, lock/order/transaction and publication sequencing; `content.queries.ts` owns precise selections/filter/order and one shared public predicate; `content.mapper.ts` owns allowlisted admin/public projections. Reusable errors belong in `content.errors.ts`, independent pure rules in `content.rules.ts`, module types in `content.types.ts`, and DTO aliases in `dto/content.dto.ts`. Controllers only parse validated context and send envelopes. The media service's Chapter-page write restriction is target-specific, before existence disclosure. Web `model` owns form schema/normalization/command shaping/error classification, `api` owns transport projection, `hooks` query/cache lifecycle, and components rendering/transient state. ### Database and failure detail

Use [data-model.md](data-model.md) as the invariant source. The current Chapter update deletes/recreates `ChapterPage`, which conflicts with P02 retained references. Implement stable ID diff and retirement. PostgreSQL uniqueness enforces Work-number and one active reference per page; active-page position uniqueness plus commit-time readiness protects races. Avoid duplicate assets only if an actual requirement emerges; the contract requires unique page IDs/positions, not unique image content. A serial winner determines each competing number/update/publication outcome; stale writes receive 409 and reload. Retry only database serialization failures within the current bounded policy, never replay a non-idempotent browser create blindly after an unknown network outcome. A failed aggregate save rolls back page/reference/event changes; prior revision remains. Independently uploaded candidates remain under P02 retention and are checked through attempt/asset reads before re-use.

Public availability uses persisted media state; reconciliation can lag physical damage. Byte-serving remains private and fails closed when storage is unavailable. Admin preview must surface an unavailable image instead of claiming publication health. Existing `MEDIA_IN_USE` protects referenced assets from removal. No external notification is enqueued by P04.

### Frontend query, access, and interaction detail

- Query keys include authenticated actor ID, Work ID, Chapter ID, and complete list filters/sort/page/limit. List/detail/readiness are server state; RHF and component state own unsaved title/text/page ordering and upload progress. On actor change/logout/403, cancel and remove protected Chapter queries; never show another actor's cached body. Reset/enable only after confirmed active ADMIN context. P03 denial fencing is the pattern; avoid broad invalidation of unrelated categories/Works.
- On create/update success, use parsed authoritative Chapter to reconcile detail and invalidate only the relevant Work Chapter lists and public metadata query if one is ever mounted. On publication success, reconcile state using returned transition and refetch the Chapter; do not show confirmed success until the authoritative detail agrees. Invalidate scoped list/detail and eligible public metadata. Cancel in-flight reads before reconciliation; prevent an older completion from replacing a newer saved revision. Handle version conflicts by retaining unsaved draft and offering authoritative reload, not automatic overwrite.
- For multi-file upload, display each candidate's pending/accepted/rejected/uncertain state and progress. Save only accepted IDs. Unknown transfer outcome checks P02 upload-attempt state before retry; independently uploaded but unsaved candidates remain marked as such. Disable conflicting saves/state actions while pending. A failed save retains draft order and the prior confirmed preview separately.
- Keep current Arabic RTL layout, order controls, confirmation dialog and preview shell. Remove manual type switch, random sample page, Markdown-like quote/image tools and fixture reader success path. Use the common safe renderer in admin preview; label unsaved vs saved preview. Keyboard reorder/removal, per-field errors, upload progress and errors, disabled/pending controls, live feedback, focus return/trap/dismissal in modal, reduced motion, target size, contrast, and responsive narrow/wide layouts require browser checks against `DESIGN-SYSTEM.md` and PLAN.md §11. Success, empty, filtered-empty, loading, background refresh, denied, unavailable, stale and retry states remain distinguishable.

### Security and privacy review

Admin reads/writes require the existing authentication middleware's active/verified account, ADMIN role before private lookup, and CSRF on unsafe cookie-authenticated requests. Validation rejects unknown fields and bounds title, number, query, text, pages and IDs. Parent Work/Chapter pairing and media class/scope/availability are checked server-side. A Work owner or moderator without ADMIN has no Chapter authority. Public reads use allowlisted metadata and indistinguishable unavailable/absent behavior; no private media address/body/history is projected. Keep global rate limits/request IDs and established log redaction. Threat cases to test: forged client type/role, cross-Work ID, foreign asset ID, unsafe link/raw markup, duplicate page IDs, stale edit, direct P02 reference bypass, unavailable media, and cache resurrection after denial. No new credential/URL/log path is introduced.
