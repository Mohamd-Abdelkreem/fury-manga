# P04 Chapter HTTP Contract

This is the P04 contract for the existing `/api/v1` route family. Local admin Chapter authoring, summary list, publication readiness, public filtering, and the title-bearing public projection are implemented in the checkout. The isolated synthetic migration rehearsal does not approve deployment against real legacy data. `@fury/contracts` Zod schemas and inferred input/output types are the executable source; API DTO aliases, runtime handlers, OpenAPI, web parsing, and tests must agree. All request objects are strict: unknown fields and incompatible type-specific fields fail validation.

## Shared wire rules

- Success uses the existing strict envelope `{success:true,statusCode,message,data,requestId,timestamp,path}`. Errors use `{success:false,statusCode,code,message,errors?,requestId,timestamp,path}`; `errors` entries have `field` and safe `message`. Do not return Prisma rows, storage keys, private byte paths, credentials, or stack traces.
- UUIDs use the current canonical content ID rule. `number` is an integer `1..2147483647`, unique per Work. `title` is NFC-normalized, trimmed, nonempty, at most 200 characters, with unsupported controls rejected. Versions are nonnegative integers. `expectedVersion` is required for PATCH and publication PUT.
- Omission in PATCH means unchanged. `textContent:null` explicitly clears a **draft or archived** text body; an illustrated Chapter rejects `textContent`. `pages:[]` explicitly clears a **draft or archived** illustrated page set; a text Chapter rejects `pages`. Create may omit its type-specific content to save an incomplete private draft. Null pages and null title are invalid. No request may submit both `textContent` and `pages`.
- A non-null text document is `{version:1,blocks:[...]}` using the existing strict schema: 1–500 paragraph, H2/H3 heading, or ordered/unordered list blocks; safe text leaves/inline bold/italic/root-relative same-site links; 512 KiB serialized maximum. No raw HTML, quote, image, embed, arbitrary attributes, or external URL. The server validates the same shape on every write and never renders submitted HTML.
- Illustrated `pages` is the _entire intended ordered sequence_, 0–500 items. Array order determines stored positions `1..N`; clients do not send mutable position values. Each entry is `{assetId}` for a new page or `{id,assetId}` for an existing page. `id` must belong to an active page of this Chapter; each existing page ID occurs at most once. `assetId` is an accepted AVAILABLE admin-scoped `chapter_page` image. Existing ID plus changed asset replaces its active association; omitted existing IDs retire their page/reference history. An unchanged ID/asset reordered in the array retains its association identity. Candidate upload alone never creates a saved page.
- Administrative detail `chapter` contains `id,workId,number,title,contentType,publicationStatus,publishedAt,version,createdAt,updatedAt,textContent,pages,readyForPublication`. `textContent` is document or null. `pages` is the active ordered array of `{id,position,assetId,assetStatus}` where `assetStatus` is the current safe `available|unavailable` editorial state; no storage key or public URL. `readyForPublication` is server-computed for current content. Admin list uses a summary with the same identity/title/number/type/state/time/version and readiness but omits body and pages.
- Public `chapter` contains **only** `id,workId,number,title,contentType,publishedAt`. Public list/detail never includes text body, pages, media IDs/URLs, admin state/version, or event history. A hidden/private/absent item returns the same 404 envelope shape. A real populated deployment must pass the separate staged migration gate before this projection is enabled there.
- Pagination uses the existing `pagination` object `{page,limit,total,totalPages,hasNextPage,hasPreviousPage}` inside list `data`; defaults page 1/limit 25, max limit 100, bounded page <=100000. Out-of-range pages return an empty `items` array and the true filtered total.

For admin routes, middleware order remains authentication (including active/verified account), ADMIN authorization, then CSRF for unsafe methods, strict validation, thin controller, service. The service rechecks parent/type/version and authorizes private ownership of referenced media; Work ownership alone and a moderator without ADMIN never grant access. Public Chapter GETs use credential-free transport: no ambient session cookies, bearer or alternate credential headers, CSRF header, or session refresh. Public routes have no private lookup result in the response. Existing global request ID, rate limiting, safe logging/redaction, and error mapping remain. Public Chapter metadata is a server API for this phase; connecting public catalog or reader pages remains P05/P07.

## State, visibility, and errors

- Allowed real state edges: `draft→published|archived`, `published→draft|archived`, `archived→draft`. Publishing requires title, number and complete valid content. Same-state requests are idempotent; other illegal edges fail. Unpublish/archive preserves historical events; later republish receives a new event ID.
- Public visibility requires the current Work to satisfy the existing published/eligible Work predicate, the Chapter to be published, and each active illustrated page to have exactly one active correct-class admin reference to an available image, with at least one page. List/detail/count use this same predicate. If any saved image becomes unavailable, public metadata disappears; the admin publication state/history do not change. Verified repair restores metadata without a publication transition.
- 400 `VALIDATION_ERROR` for malformed, unknown, unsupported, out-of-bounds, or incompatible fields, with paths such as `body.title`, `body.number`, `body.textContent.blocks`, `body.pages.0.assetId`, or `query.sort`. 401 `UNAUTHORIZED` for missing/inactive/unverified session; 403 `FORBIDDEN` for an active non-ADMIN or invalid CSRF; 404 `NOT_FOUND` for absent/wrong-parent private records and absent/ineligible public records, without revealing private identity. 409 `CONTENT_CONFLICT` for duplicate number; `CONTENT_STALE_WRITE` for version loss; `CONTENT_TYPE_CONFLICT` for incompatible content; `CONTENT_TRANSITION_CONFLICT` for an illegal state edge; `CONTENT_NOT_READY` with safe field errors for an incomplete publish or published edit. Existing 429/rate and 503/service-unavailable handling remain. Database serialization exhaustion maps to a safe conflict/reload path. Network uncertainty is not treated as a committed result by the browser.
- The response envelope's `requestId` is a safe support correlation key. Failed multi-page saves leave the prior Chapter/page/reference/event revision intact. Uploaded but unbound candidates remain private and can be inspected through the existing P02 attempt/asset API before retry.

## P02 media interface evolution

- Keep `POST /media/assets` and upload-attempt lookup for `chapter_page` candidates, `GET /media/assets/{assetId}` and authenticated `GET /media/assets/{assetId}/content` for authorized admin preview, and media reference read/lookup. Their existing strict schemas, upload idempotency key, size/type validation, auth/CSRF, and safe content delivery remain.
- After active verified ADMIN authorization, CSRF, and strict validation, generic `POST /media/references` with `targetKind:'chapter_page'` returns 409 `MEDIA_TARGET_CONFLICT` without a target lookup. Generic `PUT`/`DELETE /media/references/{referenceId}` first classify the reference ID through an authorized lookup: a found Chapter-page reference, active or retired, returns the same safe 409 before any parent/asset lookup or mutation; an unknown ID returns the existing non-disclosing 404; Work cover/background references retain their P02 write and retry behavior. Non-ADMIN callers are denied before reference lookup. The conflict reveals no parent, asset, or reference details and directs the authorized caller to edit the parent Chapter. This changes the accepted P02 generic write behavior; the shared media error enum already includes `MEDIA_TARGET_CONFLICT`, so verify that existing wire shape and align OpenAPI, contract/HTTP tests, and relevant client guidance together.
- Only Chapter POST/PATCH binds, replaces, reorders, or retires Chapter-page associations after cutover. Private media bytes are never placed in the public Chapter DTO. Do not introduce P07 reader delivery.

## Compatibility

Adding `title` to public/admin output is additive, but requiring it for POST and changing page input/generic media writes breaks older independently deployed editorial clients. Coordinate API, shared package, and web deployment in a maintenance window or gate old Chapter writes before the P04 contract is enabled. Persisted legacy Chapters must be remediated under [data-model.md](../data-model.md) before final not-null and published-readiness enforcement. Do not claim an old client can continue creating compliant Chapters.
